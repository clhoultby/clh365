Async and Await

await unwraps a promise. async wraps a return value back up in one. Nothing else about the function changes.

Every async function returns a promise

export const getUserName = async (id) => {
  const res = await fetch(`/api/users/${id}`);
  const user = await res.json();

  return user.name; // caller receives Promise<string>
};

A throw inside becomes a rejection, and a plain value becomes a fulfilled promise. Marking a function async is therefore a change to its signature, and it propagates: the caller has to await it too.

Await suspends the caller, not the program

const load = async () => {
  console.log("1");
  const res = await fetch("/api/config"); // load() pauses here
  console.log("3");
  return res.json();
};

load();
console.log("2"); // runs while load() is suspended

Nothing is blocked. The rest of load is scheduled to resume when the promise settles, and the caller carries straight on.

Where not to await

Array callbacks aren't promise-aware. forEach ignores the promise its callback returns, so the loop finishes before any of the work does:

// no — returns immediately, errors are lost
users.forEach(async (user) => {
  await save(user);
});

// yes — map produces promises you can wait on
await Promise.all(users.map((user) => save(user)));

// yes — when the order matters and they must run one at a time
for (const user of users) {
  await save(user);
}

Async functions are still just functions returning values, so the module patterns hold: export them by name, keep them pure where you can, pass their dependencies in.
