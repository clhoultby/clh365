Promises · 6 of 6

Cancellation

A promise can't be cancelled. Once created it will settle, and whoever is awaiting it will be resumed. Cancellation is something you ask the underlying operation to do, and AbortController is the standard way to ask.

One controller, one signal

const controller = new AbortController();

const request = fetch("/api/search?q=cats", { signal: controller.signal });

controller.abort(); // the request rejects with an AbortError

The controller is the handle you keep; the signal is the read-only half you hand to the operation. fetch takes one, and so do addEventListener, Request, and most modern browser APIs.

An abort is a rejection you expect

export const search = async (query, signal) => {
  try {
    const res = await fetch(`/api/search?q=${query}`, { signal });

    if (!res.ok) {
      throw new Error(`Search failed: ${res.status}`);
    }

    return res.json();
  } catch (error) {
    if (error.name === "AbortError") {
      return null;
    }

    throw error;
  }
};

Aborting isn't a failure — you caused it. Filter it out before your error handling treats it as a broken backend and shows the user a message. Pass the signal in as a parameter rather than creating the controller inside; the caller is the one who knows when to stop.

Superseded requests

The usual case is a request that's still in flight when a newer one starts. Abort the old one so its late response can't overwrite the new one:

let current = null;

export const runSearch = (query) => {
  if (current) {
    current.abort();
  }

  current = new AbortController();

  return search(query, current.signal);
};

Without this you're relying on the network to deliver responses in the order you sent them, which it does not promise.

In an effect

useEffect(() => {
  const controller = new AbortController();

  search(query, controller.signal).then(setResults);

  return () => {
    controller.abort();
  };
}, [query]);

The cleanup runs before the effect re-runs and on unmount, so a component that unmounts mid-request stops the work and never sets state afterwards.

Cancellation and cached promises

The two patterns don't mix. A promise shared by several callers isn't any one caller's to abort — the previous lesson's cache would hand out a promise someone else has already cancelled. Cache the requests nobody cancels (config, flags, reference data) and abort the ones nobody shares (searches, per-view loads).
