The Singleton Promise

Three components mount at once and each one asks for the config. That's three requests for the same data, and the last response to arrive wins.

Caching the result is too late

let config = null;

export const getConfig = async () => {
  if (config) {
    return config;
  }

  const res = await fetch("/api/config");
  config = await res.json();

  return config;
};

The cache is only populated after the response lands. Every caller that arrives while the first request is still in flight sees config as null and starts its own.

Closing that window with a loading flag means somewhere to park the callers who arrive during it, and something to notify them when the data lands — a queue, a flag and a result, all of which have to agree. A promise is that machinery already.

Cache the promise instead

// config.js
let request = null;

export const getConfig = () => {
  if (!request) {
    request = fetch("/api/config").then((res) => res.json());
  }

  return request;
};

The first caller creates the promise; everyone after that gets the same one. A promise that has already settled resolves immediately, so the same line covers "still loading" and "loaded ages ago" without a flag to distinguish them.

// three components, three calls, one network request
const [header, sidebar, footer] = await Promise.all([
  getConfig(),
  getConfig(),
  getConfig(),
]);

This works because module state is created once per module, and because the assignment happens before any await — a second caller can't slip in and start its own fetch while the first is suspended.

Failure has to clear the cache

A rejected promise stays rejected. Cache it and every future caller gets the same failure, forever:

let request = null;

export const getConfig = () => {
  if (!request) {
    request = fetch("/api/config")
      .then((res) => {
        if (!res.ok) {
          throw new Error(`Config request failed: ${res.status}`);
        }

        return res.json();
      })
      .catch((error) => {
        request = null; // let the next caller try again
        throw error;
      });
  }

  return request;
};

Note the catch re-throws. Clearing the cache is a side effect, not a recovery — swallowing the error here would hand every caller undefined.

One promise per key

Same idea for a function that takes an argument, with a Map in place of the single variable:

const requests = new Map();

export const getUser = (id) => {
  if (!requests.has(id)) {
    const request = fetch(`/api/users/${id}`)
      .then((res) => res.json())
      .catch((error) => {
        requests.delete(id);
        throw error;
      });

    requests.set(id, request);
  }

  return requests.get(id);
};

The cache never expires, which is the point for config or feature flags and wrong for anything that changes. Export a way to drop it — export const refresh = () => { request = null; }; — and you have the whole of a small data layer.
