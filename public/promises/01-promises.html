Promises · 1 of 6

Promises Are Values

A promise is an object holding a result that hasn't arrived yet. It's a value like any other: assign it to a variable, put it in a Map, return it from a function, pass it as an argument. Most of this path follows from that.

The work starts immediately

const request = fetch("/api/config"); // the request is already in flight

console.log("still running");

const response = await request; // wait for it here

Creating the promise starts the work. await only decides where you stop and collect the result. That gap between the two is where parallelism comes from (lesson 3).

It settles once, and stays settled

A promise is pending, then either fulfilled with a value or rejected with a reason. That transition happens exactly once and can't be undone.

const config = fetch("/api/config").then((res) => res.json());

const a = await config;
const b = await config; // no second request; same return value

.then() returns a new promise

const name = fetch("/api/user")
  .then((res) => res.json())
  .then((user) => user.name);

Each then produces a fresh promise for its own callback's return value, so chains compose. Returning a promise from inside a then flattens it rather than nesting — Promise<Promise<T>> doesn't exist.

Wrapping a callback API

Use the new Promise constructor only at the boundary with something that isn't promise-based — anything that hands you a subscribe and calls you back:

export const subscribeToTopic = (topic) => {
  return new Promise((resolve) => {
    
    // legacy pattern using callbacks
    subscribe(topic, subscriptionHandler: (value) => {
      resolve(value);
    });
  });
};

// ...

// consumer
const config = await subscribeToTopic(configTopic);
