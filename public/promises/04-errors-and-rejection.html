Errors and Rejection

A rejection is a value the promise is holding, not an exception in flight. It only becomes an exception at the point you await it — which is why an unawaited call sails straight past your try.

fetch does not reject on 404

export const fetchUser = async (id) => {
  const res = await fetch(`/api/users/${id}`);

  if (!res.ok) {
    throw new Error(`User ${id} request failed: ${res.status}`);
  }

  return res.json();
};

fetch rejects for network failures only. A 500 is a perfectly successful HTTP exchange as far as the promise is concerned, so the status check is yours to write — a guard clause at the top of the happy path.

Catch where you can do something

// no — every caller now has to guess whether undefined means "failed" or "no user"
export const fetchUser = async (id) => {
  try {
    const res = await fetch(`/api/users/${id}`);
    return res.json();
  } catch (error) {
    log(error);
  }
};

A catch that logs and returns nothing converts a loud failure into a quiet wrong answer. Let it propagate and handle it where there's a decision to make — a UI that can show a retry, a queue that can back off. If you catch to add context, re-throw:

try {
  return await fetchUser(id);
} catch (error) {
  throw new Error(`Loading user ${id} failed`, { cause: error });
}

Note return await here. Without the await the function returns the promise and unwinds before it rejects, so the catch never sees it. It's the one place the "redundant" await matters.

finally runs either way

export const submit = async (order) => {
  setBusy(true);

  try {
    return await postOrder(order);
  } finally {
    setBusy(false);
  }
};

No catch, so the rejection still reaches the caller; the flag gets cleared on both paths. .finally() on a chain behaves the same and passes the value or reason through untouched.

Unhandled rejections

// nothing observes this promise; the rejection surfaces as a global error
saveDraft(doc);

// yes — an explicit decision to ignore failure
saveDraft(doc).catch((error) => {
  log("draft save failed", error);
});

Fire-and-forget is legitimate for things like telemetry, but attach the catch so it's fire-and-forget on purpose rather than by omission.
