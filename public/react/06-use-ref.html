useRef

useRef is for keeping references to things that exist outside of the React lifecycle. useRef returns a object that survives re-renders but not unmounts. This is important in the case of StrictMode, which forces components to re-mount in dev builds.

Writing to ref.current does not trigger a render, and React never reads it.

It is for:

  • Keeping references to DOM nodes
  • handing the raw HTML element to non-React code
  • browser native things such as timers and subscription handlers you need to dispose later

It is not for:

  • anything the component renders — writing to a ref won't update the UI
  • Caching values from props and state
  • reading or writing during render — a ref is only safe in handlers and useEffects
// yes
inputRef.current.focus();
inputRef.current.scrollTo(0, 0);
legacyFrameworkComponent.attach(inputRef.current);
timeSinceLastPollRef.current = setTimeout(search, 300);

// no
countRef.current += 1;                                      // nothing re-renders
isOpenRef.current = true;                                   // nothing re-renders
totalRef.current = items.length - selectedItems.length;     // derive it during render
formattedStringRef.current = format(props.value);           // written during render

Example - DOM element access

Pass the ref to a host element's ref attribute and React writes the node into current when it commits.

import { useRef } from "react";

const SearchField = () => {
  const inputRef = useRef(null);

  const clear = () => {
    inputRef.current.value = "";
    inputRef.current.focus();
  };

  return (
    <>
      <input ref={inputRef} type="search" />
      <button onClick={clear}>Clear</button>
    </>
  );
};

current is null until the element is mounted, so read it from event handlers or effects — never during render.

This is for things the DOM owns and React has no prop for: focus, scroll position, and calling into a non-React framework. Anything required for the rendered output should stay in state.

Holding a Timeout id

import { useEffect, useRef } from "react";

const SearchField = ({ onSearch }) => {
  const timeoutRef = useRef(null);

  useEffect(() => {
    return () => {
      clearTimeout(timeoutRef.current);
    };
  }, []);

  const handleChange = (event) => {
    const { value } = event.target;

    clearTimeout(timeoutRef.current);
    timeoutRef.current = setTimeout(() => {
      onSearch(value);
    }, 300);
  };

  return <input type="search" onChange={handleChange} />;
};

The empty effect exists only for its cleanup — unmounting mid-debounce would otherwise fire onSearch against a component that is gone.

A timeout started inside an effect instead of a handler needs no ref — see Timers in useEffect.
