Error Boundaries

An error thrown during the React render cycle propagates up until something catches it. If nothing does, React unmounts the whole tree from the root

Therefore an error in one React Component can take down the entire page, not just the banner.

Usage

Everything inside the boundary is replaced by the fallback, so the boundary marks how much UI you're willing to lose. Consider a Pod that fails to load — it is much better to lose the Pod than the whole page.

<ErrorBoundary fallback={<OfferUnavailable />}>
  <Suspense fallback={<Skeleton />}>
    <OfferBannerPod />
  </Suspense>
</ErrorBoundary>

The boundary sits outside the Suspense so it also catches a failed download — a lazy() import that rejects its promise is an error and Suspense won't handle it.

What it doesn't catch

Only errors thrown during rendering, in lifecycle methods, and in constructors below the boundary. Event handlers, setTimeout callbacks, and rejected promises you await yourself run outside React's render and still need their own try/catch.
