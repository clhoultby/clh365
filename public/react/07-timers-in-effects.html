Timers in useEffect

A timeout started inside an effect needs no ref at all; the id is a const the cleanup closes over.

useEffect(() => {
  const id = setTimeout(onDismiss, 5000);

  return () => {
    clearTimeout(id);
  };
}, [onDismiss]);

Which one to use

If the timer starts because the component mounted or a prop changed, the effect owns it. The dep array restarts it, the cleanup cancels it, and the id is a const nothing outside the effect needs — a toast that dismisses itself, a poll that runs while a panel is open.

If the timer starts because the user did something, the handler owns it. The id has to survive from one handler call to the next so the next keystroke can cancel the pending one, and only a ref does that. The effect is left holding just the unmount cleanup — a debounced search, hover-intent before a menu opens, long-press detection.

Routing an event through state to trigger an effect instead re-renders on every keystroke to schedule something that renders nothing.
