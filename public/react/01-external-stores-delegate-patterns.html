External Stores / Delegate Patterns

An external store is a plain JavaScript object that holds state and notifies listeners when it changes. Its very similar to the delegate pattern / manager pattern you may be familiar with.

This pattern can be used for sharing state between React Components and other frameworks, or between multiple React components.

useSyncExternalStore asks for two functions: one to subscribe to changes, one to read the current value.

function useSyncExternalStore<Snapshot>(
  subscribe: (onStoreChange: () => void) => () => void,
  getSnapshot: () => Snapshot,
): Snapshot;

The Store (or 'The Manager')

// cart-store.js

// state is just a plain JavaScript object
let state = { 
  items: []
};

// listeners is a list of functions (or 'delegates') to call when the state changes
const listeners = new Set();

// 'AddDelegate'
export const subscribe = (listener) => {
  listeners.add(listener);
  return () => listeners.delete(listener);
};

export const getSnapshot = () => {
  return state;
};

// called from anywhere - React or the custom framework 
export const addItem = (item) => {
  // update the state
  state = { ...state, items: [...state.items, item] };
  
  // notify all 'delegates' that the state has changed
  listeners.forEach((listener) => listener());
};

subscribe returns its own unsubscribe function, which is how React cleans up on unmount without the store knowing React exists.

Replace state, don't mutate it

React compares the previous snapshot to the new one with Object.is. Pushing into state.items leaves the reference identical, so React concludes nothing happened and skips the re-render — hence the new object and new array in addItem.

Both sides use the same module

Nothing above imports React, so the framework you're migrating from can drive the store directly:

// cart-controller.ts
import { store } from "./cart-store.js";

export class CartController {
  private unsubscribe?: () => void;

  protected render() {
    
    // subscribe or 'add delegate' to the store
    this.unsubscribe = store.subscribe(() => {
        this.updateProperties(store.getSnapshot());
    });
  }

  private updateProperties(cart: CartState) {
    // update the DOM
  }

  
  public addToCart(item: CartItem) {
    // update the store, which will notify all listeners (including React components)
    store.addItem(item);
  }

  protected dispose() {
    this.unsubscribe?.();
  }


}

A module evaluates once and every importer resolves to that same evaluated module, so there is one state and one set of listeners for the whole app. Nothing has to be wired up to make both frameworks agree on which store they mean.
