Mirroring External State

When React goes into an existing app a screen at a time, some state stays where it already lives — an Angular service, a vanilla singleton, a web component. React has to read it without becoming its owner. The obvious move is to copy it into useState and keep the copy up to date:

The old way

const CartBadge = () => {
  const [count, setCount] = useState(cartService.getCount());

  useEffect(() => {
    return cartService.subscribe(() => {
      setCount(cartService.getCount());
    });
  }, []);

  return <span>{count}</span>;
};

This works most of the time, which is exactly why it's worth being precise about when it doesn't.

The first value is read during render, but the subscription isn't attached until the effect runs after commit. Any update the store makes in that window is never delivered — the badge renders a stale count and has no way to notice.

There are also now two copies of the same fact: the store's and React's. They stay in agreement only while every code path that changes the store also notifies this listener.

The one that can't be fixed by writing a more careful effect is tearing. React can pause a render and resume it later, so two components reading the store at different moments within one render can commit different values — a cart list showing three items beside a badge reading two.

React 18 added useSyncExternalStore for precisely this job: subscribing to state React doesn't own, without duplicating it and without tearing. The next lesson builds the store it expects.
