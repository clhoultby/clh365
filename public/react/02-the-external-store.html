The External Store

useSyncExternalStore asks for two functions: one to subscribe to changes, one to read the current value. Neither is React-specific, so the store itself is plain JavaScript that any part of the app can own:

// cart-store.js
let state = { items: [] };
const listeners = new Set();

export const subscribe = (listener) => {
  listeners.add(listener);
  return () => listeners.delete(listener);
};

export const getSnapshot = () => {
  return state;
};

export const addItem = (item) => {
  state = { ...state, items: [...state.items, item] };
  listeners.forEach((listener) => listener());
};

subscribe returns its own unsubscribe function — that's the contract React expects, and it's what lets React clean up on unmount without the store knowing React exists.

Replace state, don't mutate it

React decides whether anything changed by comparing the previous snapshot to the new one with Object.is. Pushing into state.items would leave the reference identical, so React would conclude nothing happened and skip the re-render. addItem therefore builds a new object and a new array rather than mutating either in place.

Both sides use the same module

Nothing above imports React, so the framework you're migrating from can drive the store directly:

// anywhere outside React — a service, a controller, plain script
import { subscribe, addItem } from "./cart-store.js";

addItem({ sku: "A1", qty: 2 });
subscribe(() => render(getSnapshot()));

A module evaluates once and every importer resolves to that same evaluated module, so there is one state and one set of listeners for the whole app — no wiring required to make both frameworks agree on which store they mean.
