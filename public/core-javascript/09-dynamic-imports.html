Dynamic import()

Namespaces and global scripts have no answer for "only load this code when it's actually needed" — every script tag loads up front, in a fixed order you manage by hand.

<script src="charting-library.js"></script>
<script src="app.js"></script>
<!-- charting-library.js downloads and parses even if
     the user never opens the chart -->

Load a module only when you need it

button.addEventListener("click", async () => {
  const { renderChart } = await import("./chart.js");
  renderChart(data);
});

import() is a function, not a static declaration — call it anywhere, including conditionally. It returns a promise for the module's exports, and a bundler treats it as a split point: the code in chart.js ships in its own file and downloads only when this line actually runs. This is how route-based and feature-based code-splitting work under the hood.
