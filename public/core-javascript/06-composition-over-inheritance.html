Composition Over Inheritance

Inheritance ends up with a base class with shared logic and subclasses overriding bits of it. Therefore each subclass's real behavior is scattered across multiple classes and files.

The old way

class BaseValidator {
  validate(value: string) {
    return this.check(value);
  }
  protected check(value: string) {
    return value.length > 0;
  }
}

class EmailValidator extends BaseValidator {
  protected check(value: string) {
    if (value.includes("@")) {
      return super.check(value);
    }

    return false
  }
}

New way: Compose small functions instead

Use small, single-purpose functions and compose them together. Prefer the guard clause pattern for early returns.


const isEmpty = (value) => value.length === 0;

const hasAt = (value) => value.includes("@");

const isValidEmail = (value) => {
  if (isEmpty(value)) {
    return false;
  }

  if (!hasAt(value)) {
    return false;
  }

  return true;
};

isValidEmail("a@b.com"); // true

Each function does one thing and can be tested and reused on its own. isValidEmail calls the checks it needs and combines them in completely visible way. There's no hierarchy hiding what a method actually does, and no risk of a subclass's override silently changing behavior
