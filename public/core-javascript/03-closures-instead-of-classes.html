Closures Instead of Classes

State usually means "put it on this in a class" in TS/OO code:

The old way

class Counter {
  private count = 0;

  increment(): void {
    this.count += 1;
  }

  get value(): number {
    return this.count;
  }
}

A closure does the same job without this

const createCounter = () => {
  let count = 0;

  return {
    increment() {
      count += 1;
    },
    get value() {
      return count;
    },
  };
};

const counter = createCounter();
button.addEventListener("click", counter.increment); // just works

count is private by scope, not by convention — nothing outside the closure can reach it. And because increment doesn't read this at all, it behaves the same no matter how it's called or passed around.

Only need one? Skip the factory too

use a createCounter()function when you need several independent counters. If you only need one or a singleton, the module itself is already that one shared scope and is a singleton

// counter.js
let count = 0;

export const increment = () => {
  count += 1;
};

export const value = () => {
  return count;
};

// usage
import { increment, value } from "./counter.js";

button.addEventListener("click", increment);
value(); // reads the same `count` every import shares

count here is a module-level variable, not a class field or a factory's local — but it's private the same way: nothing outside counter.js can reach it unless the module exports a way in. increment and value close over it exactly like the methods returned from createCounter() closed over their local count; the only difference is there's one shared instance instead of many, because there's exactly one module.
