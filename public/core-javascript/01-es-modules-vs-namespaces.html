ES Modules Replace Namespaces

The old way

namespace Utils {
  export function formatDate(d: Date): string {
    return d.toISOString().slice(0, 10);
  }
}

// usage, anywhere after this
// script has loaded:
Utils.formatDate(new Date());

This relies on script load order: Utils has to exist as a global (or be merged across files via /// <reference>) before anything that uses it runs. Nothing in the file declares that dependency — you just have to know the right <script> order.

The ES module way

// utils.js
export const formatDate = (d) => {
  return d.toISOString().slice(0, 10);
};

// main.js
import { formatDate } from "./utils.js";

formatDate(new Date());

Every file is automatically its own scope — no wrapping function or namespace keyword required. And the import line is the dependency declaration: a bundler or browser can trace the whole graph from it. There's no global Utils object floating around, and no possibility of load-order bugs.
