Named, Default, and Re-exports

A namespace exports everything inside it as members of one object. ES modules give you three finer-grained ways to expose things from a file, and the choice matters more than it looks.

Named exports

// format.js
export const formatDate = (d) => { /* ... */ };
export const formatCurrency = (n) => { /* ... */ };

// usage
import { formatDate, formatCurrency } from "./format.js";

Named exports mirror namespace members most closely, and they come with a real benefit: an editor can rename formatDate everywhere it's used. A default export can't offer that — every importer is free to call it whatever they like.

Default exports

// logger.js
export default function (message) { /* ... */ };

// usage — the name here is arbitrary
import log from "./logger.js";
import whatever from "./logger.js"; // same function, any name

Reserve default exports for a file with one obvious main export (a single component, a single class). For anything else, prefer named exports — it keeps renames and auto-imports reliable.

Re-exports (barrel files)

// index.js
export * from "./format.js";
export * from "./logger.js";

This is the closest thing to how a namespace auto-aggregated its members — except here it's one explicit line per source file instead of implicit merging. Use it sparingly: a barrel that re-exports an entire folder can drag in every module in that folder just to use one function, and can create import cycles in a large app. Import directly from the source file unless the barrel earns its keep.
