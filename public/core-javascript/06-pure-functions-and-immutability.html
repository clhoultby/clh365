Pure Functions and Immutability

Shared namespaces made shared mutable state easy to reach for — everything lived on the same object, so mutating it in place felt natural:

The old way

namespace Cart {
  export function addDiscount(items: Item[], pct: number) {
    for (const item of items) {
      item.price = item.price * (1 - pct); // mutates the caller's array
    }
    return items;
  }
}

Call this twice, or call it and then look at the original array elsewhere, and you get a bug that's hard to trace back — the input changed underneath its owner.

Return new data instead of mutating

export const addDiscount = (items, pct) => {
  return items.map((item) => ({
    ...item,
    price: item.price * (1 - pct),
  }));
};

const discounted = addDiscount(items, 0.1);
// `items` is untouched; `discounted` is a new array

A function that only reads its inputs and returns a new value — a pure function — is easy to reason about in isolation and safe to call from anywhere without worrying who else holds a reference to the same data. map, filter, and object/array spread are the everyday tools for this; reach for them before a for loop that mutates in place.
