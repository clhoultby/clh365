Module Scope Is Your Encapsulation

Inside a namespace, "private" was a convention, not a rule enforced by the language: leading underscores, or code left un-exported. Nothing stopped another file from reaching in — namespace members were really just properties on an object.

namespace OrderService {
  // "private" only by not writing `export` — still
  // reachable if another file merges into this namespace.
  function calculateTax(amount: number) {
    return amount * 0.2;
  }

  export function total(amount: number) {
    return amount + calculateTax(amount);
  }
}

An ES module enforces the same idea for real. Anything you don't export simply does not exist outside the file — there's no reference path to it, merged or otherwise.

// order-service.js
function calculateTax(amount) {
  return amount * 0.2;
}

export function total(amount) {
  return amount + calculateTax(amount);
}

// another-file.js
import { calculateTax } from "./order-service.js";
// calculateTax is not exported — this binding simply
// doesn't exist. Nothing to grep for, nothing to guess at.

Practical effect: you can freely rename or delete an unexported helper and know, with certainty, that nothing outside the file depends on it. That used to require a repo-wide grep and a leap of faith.
